# dot Blender Studio · v5

产品建模与动画制作 Skill。内部名称 model-product-assets 保留兼容性。

让用户拿到能用的三维资产，或一个可编辑、可复现的小成片，不只是效果图或计划。沿用 model-product-assets 的身份，保留 v4 的通用建模与引导能力，新增经实际 iPhone 4 项目验证的逐帧重建方法；不把全部任务改成 iPhone 或广告复刻。

## 先决定交付，而非先扩资产库

- 只要模型：走 [模型规范](references/model-workflow.md)，不强加视频。
- 原创产品/MG 小片：定用途与范围，再走 [动画流程](references/animation-workflow.md)，只制作镜头需要的模型。
- 跟随指定原片重建：先核参考与帧范围，再读 [精确参考重建](references/precise-reference-reconstruction.md)。不要用通用转台替代原片运动，也不要把第三方上传者认作品牌官方。
- 没有想法：用 [零想法引导](references/idea-guide.md) 给少量用途、风格和小 Demo 选项。结合用户主动提供的项目，不搜索无关私人资料。已授权代选则记录推荐与假设继续；关键身份、权利或范围不明才询问。
- 可打印/制造件：本流程不提供该保证，另定公差、实体、壁厚、装配、切片等检查；STL 可打开不等于能打印。

最低任务约定：对象/准确型号或原创类别、用途、风格、模型或视频、输出格式；视频补时长/画幅/声音/参考与可接受相似度。区分“参考风格”“镜头学习重建”“严格对齐”三种目标。缺失但可逆的设置可说明假设，不把沉默当验收，不无限访谈。

## 执行要点

1. 核实际建模、渲染、回导、编码工具与可写位置，尊重现有工程和环境。缺工具报告缺口，不私自安装、换环境或以图片冒充三维。
2. 先核型号、尺寸证据、轮廓和结构，再做材质与必要变体。颜色数、实例数不是独立结构数；保留品牌与去品牌的正确区别。
3. 动画先拆镜与最小资产，再做关键姿态低清对比和低清全片。严格匹配任务冻结源文件、零基帧范围、PTS 与准确 FPS；普通原创任务不强加逐帧参考分析。
4. 接受的小样可延展到明确约定的连续范围。冻结已验收段及哈希，新镜头分别匹配，不循环旧段充数、不静默重渲已通过段。
5. 正式渲染前冻结模型/镜头表/设置并测成本。检查整数帧及运动模糊涉及的子帧旋转连续性；关键帧好看不代表中间帧正确。允许断点续算，但不得混入来源不明的旧帧。
6. 技术、独立视觉、用户验收分开记录。完整帧序列、完整解码和正确帧号不证明像素级还原；全帧接触表不等于全片实时播放。残余差异必须如实列出。
7. 交付可编辑工程、约定导出、预览/成片、来源、依赖、QA 与复现说明。重开交付副本测试，不只检查工作目录。对比版完整保留两路画面，标签放画外，声音明确来源与区间。

## 按需辅助与证据

- [视频技术检查](scripts/check_video.py)：帧数、尺寸、有理数 FPS、时长、音轨存在性与严格完整解码。不检查视觉相似度或声音内容。
- [帧范围计划](scripts/frame_plan.py)：在已确认的恒定帧率与源帧范围上生成精确有理数时间、切点和输出映射，不自动发现剪切或读取源 PTS。
- [包清单](scripts/package_manifest.py)：生成/核对相对路径、大小和 SHA-256，不证明权利或艺术质量。

[模型规范](references/model-workflow.md) 保留尺寸来源、分件、配色/Logo、GLB 实际回导及批量交付要求。模型任务和视频任务的交付矩阵不同，不无故增加格式或全品牌目录。

[案例一：iPhone 8](references/iphone8-case.md) 是两款金色模型和 22 镜头 720p 无声学习作品。[案例二：iPhone 4](references/iphone4-case.md) 是 317 帧原生时序的开头产品镜头，用户接受整体结果但确认仍有细节差异。案例不是所有产品已完成、1:1 精确、制造 CAD、原片纯 CG 或任意机器性能的保证。

默认不打包他人原视频、音乐、参考截图。公开可观看、用户接受成片、署名或去 Logo 都不等于取得再发布许可。比较版、商标、界面与声音分别核权利；生成、交付、上传、公开发布是不同状态。

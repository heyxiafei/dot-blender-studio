# 实测案例：iPhone 4 开头产品镜头学习重建

证据核实与用户验收日期：2026-10-23。本节是已发生项目的事实摘要，不是新任务默认参数、复制许可或任意机器保证。原项目和视频另行交付；本 Skill 不包含其模型工程、官方原片、声音或屏幕图像。

## 来源为什么可信

[Apple iPhone 历史产品页](https://web.archive.org/web/20101014085340/http://www.apple.com/iphone/) 和 [历史设计页](https://web.archive.org/web/20100922073714/http://www.apple.com/iphone/design/) 都指向 iPhone 4 视频。当年的链接、Apple 原始媒体路径、归档重定向、媒体时间戳和实际画面共同确认是 2010 iPhone 4 Design 影片，而非把个人上传账户误称官方。

[当时的媒体链接记录](https://forums.whirlpool.net.au/archive/1458925?p=26) 指向 Apple 的 reference MOV。该 [reference MOV 存档](https://web.archive.org/web/20100626111252/http://movies.apple.com/media/us/iphone/2010/tours/apple-iphone4-design_video-us-20100607_r848-9cie.mov) 实际只有 352 bytes、零视频流，包含真正媒体的相对文件名；后续取得的完整媒体为 126,808,153 bytes、374.040707 秒。较晚的存档抓取日期没有改变它的 iPhone 4 身份。这些证据不证明原片是纯 CG，也不表示取得其再发布权。

## 从小样到确认范围

最初样段为源零基 144–263 inclusive，120 帧，原生 2997/125 fps，5.005005005 秒。小样已被接受后，范围扩为“从第 1 秒到首次人物出现之前”：

- P1：源 24–54，31 帧，平躺机身、底部接口转向音量键侧。
- P2：源 55–103，49 帧，斜向背板转向 SIM 托盘侧。
- P3：源 104–134，31 帧，音量键微距及金属高光。
- P4：源 135–340，206 帧，背板特写拉远，经音量键侧转至正面。

总计 317 帧，输出帧为源帧减 23；第一源帧 PTS 1.001001001 秒，exclusive 结束边界 14.222555889 秒，时长 13.221554888 秒。源的 2997/125 等于 23.976，但不是 24000/1001。最终保持原生节奏，没有为凑整数秒改成 24 fps；不含采访或后续产品段。

## 真三维重建与局部近似

使用 Blender 4.3.2、Cycles CPU。工程有独立机身/玻璃/按键/接口/SIM/标识等几何、相机、材质与灯光；原片整帧没有映射到平面冒充模型。重开报告记录前三镜工程 312 个 mesh + 2 个 curve，长镜工程 307 个 mesh；数量只说明工程构成，不是质量指标。

相机与投影根据实际画面拟合，不是原厂制作数据。唯一列出的图像是已打包的 286×428 屏幕界面贴图，应用于真实机身屏幕面；它包含 Apple UI，不能称全部图形都由此项目原创，也不能因嵌入 BLEND 就称权利已清。

低清关键姿态对比、特征点拟合和连续帧审阅后渲染。原先已接受的源 144–263 对应 120 张重建 PNG 在扩展片中保持字节级一致，哈希逐张核对；新增镜头没有循环旧样段。汇总后有 111 张 RGB 和 206 张 RGBA 输入，编码使用另建的统一 RGB 副本，不覆盖接受版 PNG。

P2 的 89→90 出现 Euler 等价表示分支跳变，整数帧姿态看似正确但子帧运动模糊出错。改为相对上一帧连续的 Euler 表达并定向重渲 89/90。项目报告记录修前后整数矩阵最大差约 5.07e−7、1/8 帧步长最大朝向变化约 0.006404 rad。这里记录实际修复，不将该阈值写成所有项目标准。

## 成片、技术 QA 与独立视觉检查

- 比较版：848×1044、H.264、317 帧、2997/125 fps，视频流 13.221555 秒。上方原片、下方独立重建，每路完整 848×480；标签与声音说明在画外。
- 声音：同一源区间的原始混音，含原有人声时仍保留；没有分轨或变速。AAC 重新编码而非字节复制，44.1 kHz 双声道，音频流约 13.220998 秒。已有 QA 的解码相关性为 0.999204，检查 583,071 samples/channel；此数不等于版权许可或完整听感验收。
- 自有重建版：848×480、同样 317 帧/时序，无音轨。
- 已有技术 QA：完整解码、317 帧两路与各自输入的对齐核对，编码 RGB MAE 最大 1.83394（该次阈值 2）；这比较的是编码输出与其输入，不是原片与模型相似度。
- 已有独立视觉审阅：顺序接触表覆盖全部 317 帧，复核三个切点、保护区接缝和源 88–91 原尺寸帧。没有将接触表说成最终视频完整实时播放。
- 后续用户明确接受整体还原效果，并指出一些细节仍有小区别。验收为本次用途“可用”，不是像素完全一致，也不自动授权代发社交平台。

残余：P1 光照响应与端部细节偏平；P2 铭文、SIM 托盘与反射；P3 金属颗粒、按键圈与高光；P4 屏幕对比度、听筒/Home 几何、后段玻璃与地面反射仍有区别。

## 工程包与验证边界

独立工程 ZIP 5,223,895 bytes，SHA-256 `33bf5228df9056bcbaed034327cd545a28f582e5ada91a65762b68d007cd2b94`，含 28 个清单文件及 MANIFEST.json。已复核 ZIP CRC、28 条大小/哈希、7 个 Python 脚本语法。工程内附冻结 BLEND、相机拟合/参数、渲染与组装脚本、QA 和无声 MP4；不包含 PNG 序列，也不包含官方 MOV、截帧、音轨。

已有 QA 证明工程重开与依赖打包情况；这次核对没有执行从空目录完整重渲 317 帧，也未在新用户机器安装。保留检查脚本只比较特定相机/材质状态，不能升级成全网格几何等价证明；120 张原 PNG 字节保持是另外直接核实的证据。复现路径为重开两个冻结场景渲染，再用相对路径脚本组装无声重建；场景修改后不能复用旧 PNG 的“已存在就跳过”结果。

案例证据位于另行交付工程中的 opening-product-comparison/qa/source-scope.json、delivery-qa.json、visual-review.json、source-package-qa.json，和 opening-three-shots/euler-continuity-verification.json、full-shot/qa/project-reopen.json；这些不是本 Skill 自带文件。

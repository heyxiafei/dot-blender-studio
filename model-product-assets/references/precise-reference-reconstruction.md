# 指定原片的精确学习重建

适用：用户希望模型动画跟随某个真实片段的构图、动作、节奏，或制作可比较的重建。不是默认给所有小 Demo 增加复杂流程。目标是可证明的忠实度，不是声称“原片工程”“完全一样”。

## 1. 参考作品、上传者、媒体文件与制作方式是四件事

记录作品标题、品牌/创作者、可访问页面、上传账户及证据、文件来源链、取得日期和哈希。区分：
- 官方页面或品牌域名原始媒体有明确关联，可支持“品牌官方发布的作品”。
- 个人作品集、平台转发、粉丝上传只证明该账户发布了这个副本，不能单凭名称、徽标或画面认定其为官方上传或版权方。
- 历史官方页面、当时媒体链接、存档重定向、媒体内时间戳和实际画面可构成来源链；存档抓取日期不等于作品生产日期。
- 官方发布不证明所有镜头都是 CG；没有制作证据不推断“原广告全部 Blender/纯三维制作”。独立重建采用三维也不能反证原片制作技术。

需要原视频时只用可合法访问的渠道，不绕过登录、DRM、安全提示或下载限制。小型 reference MOV 可能只含另一个媒体文件名而无视频流；以 ffprobe 的实际 streams、时长、大小和帧内容确认拿到的是媒体而非跳转描述文件。来源不够强就用“所提供参考片”，并说明未核实事项。

将原文件、元数据与抽帧放在独立只读参考区域。冻结后不覆盖源；公开交付优先写来源链接与事实，不附原媒体。

## 2. 把自然语言边界转成可核验的帧范围

“第 1 秒开始”“到人物出现之前”“这一转身结束”不是随意四舍五入的秒数。核源 FPS、time base、起始 PTS、逐帧 PTS 与是否可变帧率，按画面逐帧确认边界。记录用户语义边界与所选实际帧边界的偏差。

对每个镜头保存：源零基起始帧、exclusive 结束帧、首帧 PTS、结束边界 PTS、输出帧范围/编号规则、主体、构图、运动、转场与不确定性。检查切点前后帧；场景检测只作候选，微距/反光变化不一定是剪切，人物出现不能漏入范围。

CFR 且已知 PTS 起点时，N 帧时长为 N / 精确 FPS；exclusive 结束边界不是最后一帧的 PTS。VFR 必须按实际 PTS 和帧时长建映射，不能仅用平均 FPS。保留有理数，不先取 23.98/24 再计算。

案例中的 2997/125 恰为 23.976，不是 24，也不等于 24000/1001。源 24–340 inclusive 等同 [24,341)，共 317 帧；其时长 13.221554888 秒。源 144–263 共 120 帧，原生 5.005005 秒。它们是案例事实，不是新任务默认帧率/时长/切点。若用户明确要 5.000 秒，可提出 120 帧改为 24 fps 的透明约 0.1% 加速选择，并同步说明声音与比较的变化，不擅自规范化。

[帧范围计划脚本](../scripts/frame_plan.py) 可检查 CFR 区间和算术，不能替代源流探测、视觉切点验证或 VFR PTS 分析。

## 3. 参考、模型、画面比较各自分离

- 三维主体应有可编辑实体/表面、分件、材质与相机，在不同视角保持合理投影。不要把原视频整帧贴在单个平面上当作三维重建。
- 原片可以作为相机匹配参考或比对上路，但必须清楚区分参考图层与生成渲染。屏幕界面可在真实机身显示面上使用贴图；披露第三方 UI/图像来源，不称每个图标都是重新建模。
- 从轮廓、关键点、比例、遮挡判断物体/相机运动。相同投影可能有多种解，拟合相机不等于找回原厂焦距/轨道；明确采用的重建解。
- 模型版本、根控制器、相机、灯光、参照图层分开命名；原片不进入独立自有重建的渲染层。

## 4. 先匹配低清关键姿态，再匹配连续运动

选择每个镜头的起、中、末及遮挡/运动转折帧。低分辨率并排或叠加检查：轮廓、机身占屏、透视、边角/孔位/标志投影、画面重心、运动方向、背景/地面。重点顺序通常是身份和轮廓 → 相机/姿态 → 尺度/位置 → 灯光材质 → 微细节；避免靠亮度补错姿态。

必要时拟合多个可靠二维特征点，记录所用点、目标误差与残余。不能仅凭 bbox 相似、平均像素差或单帧美观通过；白背景会稀释误差，反射变化会夸大像素差，点位本身也有不确定性。关键帧匹配后看全部连续低清帧，检查加减速、速度符号、运动方向、剪切与结尾。测代表帧时间再估渲染预算。

## 5. 小样验收后延展，保护已接受段

先交付约定的一段小样。接受后，继续范围必须清楚，例如“从开头一秒到第一次人物出现之前”，不能擅自扩整片或循环小样凑长度。新增镜头分别求解，共用合适模型但不假设共用同一轨道。

为已接受段记录源帧范围、原始渲染文件名和 SHA-256；标记其模型/曲线/材质依赖。新增前后延展优先改保护范围外的曲线，边界匹配位置、朝向、速度和反光。检查曲线插值、父层级、灯光等修改是否会污染保护区。必须修改已接受段时先说明原因、范围与影响；不要把旧“接受”沿用到新像素。

可保留旧段原 PNG，分段渲染新增部分后按显式 frame map 组装；核每个源帧只对应一次输出。编码为统一 RGB/RGBA 时建立副本，不覆盖验收 PNG；分别证明原字节未改和可见像素是否保持。混合像素格式有时触发编码滤镜重置，应在编码输入层显式统一。不要以新的编码哈希证明原 PNG 未变。

## 6. Euler 与子帧运动模糊陷阱

等价 Euler 角可能在相邻整数帧采用不同分支；整数姿态矩阵看起来相同，插值却绕远路，开启 motion blur 后出现瞬间长拖影、翻转或假闪光。逐帧渲完才发现时，不要先改模型或用裁剪/降亮度掩盖。

检查相邻姿态矩阵、Euler 曲线、父层级与快门覆盖的子帧。用当前项目适合的连续 Euler 表达（例如相对前一帧的兼容解），或处理好符号与插值的 quaternion，不能假设随意转成四元数自动修好。保留本应存在的旋转方向和圈数。修前后比较整数帧矩阵、子帧方向变化及像素，再重渲受影响帧与相邻检查帧。

本案例仅在 89→90 的分支处出现问题，修复等价表示后定向重渲 89/90。具体帧号、1/8 帧采样和数值阈值只是该例证据，不复制为通用标准；新片按快门宽度、旋转速度与尺度选测试。

## 7. 比较版式、音频区间与标注

两路必须来自同一帧映射，保持相同宽高比、完整画幅和明确缩放规则；用户未要求时不裁原片以隐藏差异，不为填竖屏拉伸。用画外窄标签区标注“参考原片”“独立三维重建”和声音来源，避免遮住手机或把原片误认成原创。

音频按约定选择静音、授权独立音乐或原片同一区间。原混音有解说就如实说含人声，不擅自宣称纯配乐或分轨；不得把全片随意一段配到重建上。按实际首帧 PTS 与 exclusive 结束 PTS 截取，保持节奏/采样率策略透明；对 AAC 等编码延迟和尾部 padding 检查实际同步。完整解码、相关性与听感检查是不同证据，音轨存在性不能代替它们。

“相同源帧索引”和“编码后 panel 对输入平均误差小”仅证明组装正确，不证明模型与原片像素一致。原片与重建之间的差异要独立看。

## 8. 全范围验收、可复现与权利边界

技术覆盖所有帧、切点、保护区边界、终止画面、最终编解码和音频；视觉顺序覆盖全部范围，并以原尺寸复核微细节/异常帧。独立审阅与创作者自检分开，用户接受状态另记。最终写出仍不同的轮廓、反射、材质、界面、字样、微结构等，不将“够用”升级为“完全一致”。

交付便携工程及相对路径重建脚本，说明准确工具/渲染器/依赖、已测范围及未测事项。模型工程能独立重渲自有部分；未附官方源就应明确无法凭此包重建“含原片+原声”的比较版。源工程重开、代表帧重渲、整片重渲、新机器端到端安装是四个不同强度的验证。

公开分享要分别审查原视频、音乐/人声、界面贴图、商标与外观素材的权利。明确署名与“学习重建”标签有助于不混淆，但不提供转载许可。用户认为视频可发布不等于要求你代发，也不解决版权问题；不能在权利未核实下承诺“可放心商用/随意转载”。Skill 分享包只含通用方法、公开来源链接与经脱敏案例事实，不附官方媒体、界面纹理或私人资料。
